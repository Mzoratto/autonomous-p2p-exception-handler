### Audit data available to the UI

- `get_case()` returns `case_id, invoice_id, status, invoice, state, updated_at, checkpoint_id, submitted_review, audit[]`; each audit entry has `event_id, case_id, timestamp, event_type, actor, data`.
- `RESOLUTION_PROPOSED` / `RESOLUTION_REVISED` data: `action, rationale, evidence_refs, confidence, information_request, error, attempt` (0-based) plus hashes. `CRITIQUE_PASSED` / `CRITIQUE_FAILED` data: `valid, issues, recommended_changes, confidence_adjustment, iteration, exhausted`. The post-Critic confidence of a rejected attempt (0.75 in scenario 03) is not recorded anywhere.
- `HUMAN_DECISION_RECEIVED` and `CASE_COMPLETED` are written by `save_case` with the full `HumanReview` / `CaseOutcome` as data.

### Streamlit 1.67.0 test behaviour (probed with `AppTest`)

- File-based pages registered through `st.navigation` work; `at.switch_page("<path relative to repo-root app.py>")`, `at.query_params[...] = v`, `st.switch_page(page, query_params=...)`, `at.pills[i].set_value()`, `at.toast` after a flash-and-rerun all work.
- A state-driven `@st.dialog` renders inline and its buttons are clickable.
- `st.switch_page` must be called from the script body (`if st.button(...): st.switch_page(...)`), not from a callback. Setting `st.query_params` in a callback is fine.
- `st.context.url` and `st.context.timezone` are `None` under `AppTest`, so UI tests exercise the fallbacks (relative link, UTC). In a browser `st.context.url` is the origin only (for example `http://127.0.0.1:8503`, no path or query) and `st.context.timezone` is the browser's IANA zone.

### Remaining known limitations (after Phase 7)

- **R17, override source without an AI proposal.** When a case reaches review with no AI resolution (a high-value exact match, or a model outage before the Resolver answered), `human_review_node` and `finalize_node` compare the decision with a default APPROVE, so a human Reject or Request info is stored as `HUMAN_OVERRIDDEN`. The stored value is unchanged; the dashboard and the override metric count an override only when an AI resolution exists (`docs/audit-remediation.md`).
- **No authentication.** The reviewer name comes from `P2P_REVIEWER_NAME`; there is no login or assignment model.
- **One SQLite file, commands serialized.** Processing and reviews take a global file lock, so they run one at a time; the lock relies on `flock` and a local file system. Reads do not wait.
- **Live model untested against the real API.** The OpenAI provider (timeouts, retries, 401/403, 429 including `insufficient_quota`, 5xx) is tested with an injected fake client only.
- **Unreadable stored data.** A case whose state cannot be read shows "Needs recovery" with technical details, but its audit trail is not shown. An unreadable stored invoice on the same PO, or with the same invoice number, still blocks processing of a new invoice, because duplicate and reservation checks must read it.
- **Identity lookup trusts normalized ids.** `claim_case` compares `invoice_id` directly (indexed). A legacy row written outside the `Invoice` model with a non-normalized id (lower case, surrounding spaces) would not be found.
- **Resolver outage.** If the Resolver is unreachable, its fallback ESCALATE (confidence 0) appears as the recommendation chip; the reviewer note says the model was unavailable.
- **Docker volumes from the old root image** need a one-time `chown` to uid 10001 (README).
- **Python 3.15** is not in the CI matrix: uv 0.11.29 has no 3.15 build to test against.
- **Streamlit-owned controls.** The tab-strip scroll arrows are 18 × 35 px (below the 24 px target size; tabs are also reachable by keyboard and swipe), and disabled buttons use Streamlit's low-contrast grey (inactive controls are exempt from WCAG contrast).
- **Accepted design approximations.** Nav count instead of a badge, Streamlit's collapsing sidebar instead of a top row on narrow screens, coloured text instead of chips in the Cases table, a popover with a copyable link, a top bar that is not sticky; KPI trends stay hidden until enough history exists.
- **Not built from the Phase 7 plan:** sticky review queue and decision columns at ≥ 960 px (not in the Phase 7 scope that was approved).

### Formatting helpers (`src/p2p/ui/viewmodels.py`; none exist today, `DecimalDisplay` converts through `float` and is deleted)

- `format_money(amount, currency) -> str`: `Decimal` quantized to 0.01; prefix `€` for EUR, `$` for USD, `£` for GBP, otherwise `"<CUR> "`; thousands separators. `format_money("2200", "EUR") == "€2,200.00"`.
- `format_duration(seconds) -> str`: under 60 s "just now"; under 60 min `"26m"`; under 24 h `"2h 14m"`; else `"1d 3h"`.
- `format_delta(seconds) -> str`: under 60 s `"+1.84 s"`, else `"+" + format_duration`.
- Timestamps: parse ISO; a naive value is UTC. Local time uses `zoneinfo.ZoneInfo(st.context.timezone)`; if that is missing or invalid, use UTC and append " UTC".

### URLs and state

- Query params: `case=<case_id>` on `/review` and `/cases`; `status=<view>` on `/cases`, where view is one of `review`, `approved`, `rejected`, `request_info` (absent means all).
- Flash: `st.session_state["flash"] = {"kind": "toast" | "error", "text": str}`; rendered once at the top of every run and removed.
- Reviewer identity: `current_reviewer() -> str` in `src/p2p/ui/identity.py` returns `os.getenv("P2P_REVIEWER_NAME", "Demo Reviewer").strip() or "Demo Reviewer"`; `initials(name)` is the first letter of the first and last word, upper-cased.

Projection. `casefacts.project(invoice: dict, state: dict) -> dict` returns the non-timestamp columns (`total_cents` = total quantized to 0.01 × 100; `ai_action` / `ai_confidence` from `state.resolution`; `outcome_*` from `state.outcome`; exception fields from `primary_exception`). `claim_case` sets them and `created_at` on the new row. `save_case` computes the projected values, then assigns only the attributes whose current value differs (R18); it sets `review_requested_at` only when it is NULL and the status is PENDING_REVIEW, sets `completed_at` from the outcome only when it is NULL and the status is COMPLETED, and sets `last_error` to NULL only when the status changes and it is not already NULL. `updated_at` keeps its existing rule (changes only when status or `state_payload` changes). ### Phase 6: backend hardening

1. Non-blocking reads. `SqliteRepository.try_command_lock()` is a context manager that yields `True` after acquiring the same RLock and `flock` without blocking (`acquire(blocking=False)`, `LOCK_EX | LOCK_NB`), or `False`. `refresh_open_cases()` returns immediately when it yields False. `get_case` uses it: acquired → today's behaviour; not acquired → the stored row plus audit, `checkpoint_id=None`, `submitted_review` as stored, and `"busy": True` (False otherwise). The UI disables the decision panel for a busy case with the caption "This case is being processed. Refresh in a moment." Commands (`process_invoice`, `review_case`) keep the blocking global lock unchanged.
2. SQLite. In `Database.__init__` register an engine `connect` listener that runs `PRAGMA journal_mode=WAL` and `PRAGMA busy_timeout=5000`; in `create_runtime` run `PRAGMA busy_timeout=5000` on the checkpointer connection. `Database.__init__` raises `ValueError("P2P_DATABASE_URL must be a sqlite:/// file path")` for any URL that does not start with `sqlite:///` or whose path is `:memory:`; delete the `InMemorySaver` fallback branch and its import from `service.py`.
3. Indexed lookups. `claim_case` selects only rows where `case_id == :case_id OR upper(trim(invoice_id)) == :invoice_id` and applies the existing identity logic to them. `reserved_quantities` selects `case_id, invoice_payload` where `po_number` equals the argument (`IS NULL` when it is None), `case_id != exclude` and `outcome_action` is null or not `"REJECT"`, and sums the line quantities as today.
4. OpenAI. `OpenAI(api_key=..., base_url=..., timeout=float(os.getenv("OPENAI_TIMEOUT_SECONDS", "30")), max_retries=int(os.getenv("OPENAI_MAX_RETRIES", "1")))`; `responses.parse(..., store=False)` (the installed SDK 2.54.0 accepts `store`). Add two exception classes to `src/p2p/ports.py`: `ModelUnavailableError(RuntimeError)` and `ModelAuthenticationError(RuntimeError)`. `OpenAIModelProvider.structured_response` converts `openai.APIConnectionError` (includes timeouts), `RateLimitError` and `InternalServerError` into `ModelUnavailableError`, and `openai.AuthenticationError` into `ModelAuthenticationError` (R19: authentication failure is never treated as an outage). Both providers set `self.last_call` after each call: live `{provider: "openai", model, response_id, input_tokens, output_tokens, latency_ms}`, mock `{provider: "mock", model: "mock"}`. The three AI nodes add `"model_call": getattr(<service>.provider, "last_call", None)` to their audit payload.
5. Outage and authentication routing. Add `model_unavailable: bool` to `P2PState`; each AI node's broad `except` sets it to True when the exception is a `ModelUnavailableError`, and logs with `logger.exception`. Each AI node gets `except ModelAuthenticationError: raise` before the broad `except`, so the error leaves `graph.invoke`; the case stays PROCESSING, step 6 stores `last_error`, and resubmitting the same invoice resumes it. Replace the fixed edges `investigate → resolve` and `resolve → critique` with conditional edges that go to `"policy_check"` when `model_unavailable` is true; `route_after_critique` also goes to `"policy_check"` in that case. Policy already requires review whenever `model_error` is set.
6. Errors and time. In `process_invoice` and `review_case`, wrap `graph.invoke` and the final `_reconcile` in `try/except Exception`: call `repository.record_error(case_id, f"{type(exc).__name__}: {exc}")` (itself guarded so it cannot mask the original), then re-raise. `save_case` stamps the HUMAN_DECISION_RECEIVED event with `human_review.reviewed_at` and CASE_COMPLETED with `outcome.completed_at` (as naive UTC) instead of the save time. On a case with status key `recovery`, the case detail shows `last_error` under "Technical details" and a button "Retry processing" that calls `app.process_invoice(Invoice.model_validate(case["invoice"]))`.
7. Logging. `logging.getLogger("p2p")`; `main()` calls `logging.basicConfig(level=os.getenv("P2P_LOG_LEVEL", "INFO"), format="%(asctime)s %(levelname)s %(name)s %(message)s")` once; `process_invoice` and `review_case` log start, finish (status, milliseconds) and failure with the case id.
8. Setup screen. One function `setup_screen(title: str)` in `components/shell.py` renders the title, the two fixes (set a valid `OPENAI_API_KEY` in `.env.local` and restart the app, or set `DEMO_MODE=true`) and calls `st.stop()`. `main()` wraps `service()`: on `RuntimeError` it calls `setup_screen("Live mode needs an API key")`. Every UI call site of `app.process_invoice` (Process run, "Run all 10 scenarios", "Retry processing") catches `ModelAuthenticationError`, sets `st.session_state["p2p_setup_error"] = "auth"` and reruns; `main()` checks that key right after `service()` and calls `setup_screen("Live mode cannot authenticate")`, which for this case also shows a "Try again" button that removes the key and reruns.
9. Tests: a second thread holding `command_lock()` while the main thread calls `get_case` and `query_cases` → both return within 1 s and `get_case(...)["busy"] is True`; WAL is active (`PRAGMA journal_mode` returns `wal`); non-SQLite URL raises; `OpenAIModelProvider` with an injected fake client: parsed output returned and `last_call` filled, `output_parsed is None` → `ValueError`, `APITimeoutError` → `ModelUnavailableError`, `openai.AuthenticationError` (built with an `httpx.Response(401, request=httpx.Request("POST", "https://api.openai.com"))`) → `ModelAuthenticationError`; a provider that raises `ModelUnavailableError` in the Investigator leads to PENDING_REVIEW with exactly one model call and `model_error` in `triggered_rules`; a provider that raises `ModelAuthenticationError` in the Investigator makes `process_invoice` raise it, leaves the case PROCESSING with `last_error` set and records no `INVESTIGATION_COMPLETED` event; an injected `graph.invoke` failure sets `last_error` and the next identical `process_invoice` completes and clears it; CASE_COMPLETED audit timestamp equals `outcome.completed_at`. Run the four concurrency tests 20 times: `for i in $(seq 20); do .venv/bin/pytest -q tests/integration/test_audit_controls.py -k concurrent || break; done`.

## Assumptions & contingencies

- Streamlit stays at the locked 1.67.0. New dependency bumps happen only in their own chore PR, never inside a phase PR.
- IBM Plex is self-hosted. If the font or licence download fails, set `font = "IBM Plex Sans:https://fonts.googleapis.com/css2?family=IBM+Plex+Sans:wght@400;500;600;700&display=swap"` and `codeFont` likewise, skip `static/fonts`, and list it as a deviation.
- The reviewer name comes from `P2P_REVIEWER_NAME`; there is no login or assignment model.
- Streamlit approximations are accepted: count in the nav title instead of a badge, a collapsing sidebar instead of a top row, text colours instead of chips inside the Cases table, a popover with a copyable link instead of one-click copy, a top bar that is not sticky.
- Screenshots are kept on the orphan branch `screenshots`, never on `main`.
- A failed OpenAI authentication stops processing with the setup screen instead of routing the case to review.
- A human decision on a case without an AI resolution stays stored as `HUMAN_OVERRIDDEN` when it is not Approve; only the display and the override metric account for it.
- Severity and AI results shown are what the domain produces, which differs from the design's sample data.
- The policy checklist has 11 rows, not the design's 9.
- KPI trends stay hidden until the history conditions in Phase 5 are met; note length for Approve and Reject is 3 characters; no dark mode.
- Commands stay globally serialized; there is no `FAILED` status.
- If the three-container workbench does not sit in one row at 1440 px, use `st.columns([1, 2.6, 1.2])` and accept stacking only at Streamlit's own breakpoint.
- If a pandas `Styler` disables row selection in `st.dataframe`, drop the Styler and keep plain text cells.
- If `st.context.url` is empty, show the relative link `/cases?case=<id>`.
- If any test constructs `Database(...)` with a non-file URL (check with `grep -rn "Database(" tests`), keep the Phase 6 guard in `create_runtime` only.
- Docker verification in Phase 7 needs a running Docker daemon; if it is not running, report the build as unverified in the PR.
